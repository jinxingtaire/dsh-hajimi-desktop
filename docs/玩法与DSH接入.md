# 哈吉咪桌宠：别靠太近

2026-11-17 · 玩法与技术草案 v0.1

最新规则：按用户试听分类保留 13 条音效，使用左右声道与距离升调；回血表现为舔毛。当前准确规则见 [当前音效规则.md](当前音效规则.md)，下文涉及早期口香糖、吧唧嘴与历史音效数量的内容仅作草案记录。

## 核心体验

用户亲手控制两只猫之间的距离，看它们从装作无事，到嘴硬叫板、终于打成烟雾，再分开嚼口香糖装没事。笑点来自“嘴硬的过程”和“打完若无其事”的反差。

最小循环：独处 → 用户加猫 → 拖近 → 偏头警告 → 炸毛应激 → 贴近吸附 → 烟雾打架 → 分开嚼口香糖 → 恢复独处。

“抵抗代码”是猫的可见表演：偏头、斜眼、拱背、尾巴僵直、嘴巴开合。用户不需要看一个数值面板才能理解猫正在应激。

## 体验节奏

距离使用两只猫中心距除以平均可见体宽 D，数值是样机调试起点，不是验证后的最终参数。正式动画的可见角色边界要单独标定，不能拿含透明留白的视频画框宽度代替体宽。

| 阶段 | 触发 | 用户感受 | 画面重点与动作 | 声音 | 文案 |
| --- | --- | --- | --- | --- | --- |
| 独处 | 一只猫，或距离 > 2.15D | 看起来还挺乖 | 呼吸、眨眼、轻摆尾；单击给短回应 | 单击喵 / 老无，平时安静 | 不常驻气泡 |
| 偏头 | 距离 ≤ 2.15D | 它注意到对方了 | 两只转向对方，头缓慢歪过去、眼睛眯起 | 一次短“老无……” | 少量拟声，不写系统状态 |
| 炸毛 | 距离 ≤ 1.4D | 快要绷不住了 | 拱背、毛尖立起、小幅抖动、耳朵后压 | 老无老无 / 那个那个 / 咕噜轮换 | “那个那个那个！” |
| 吸附 | 距离 < 0.86D，且双方已应激至少 650ms | 终于忍不住了 | 260ms 内弹向中点，短促压缩后消失 | 短扑击声 | 不打断节奏 |
| 打架 | 吸附结束 | 荒诞释放 | 约 2.4s；一个共用烟雾团，偶尔伸出猫爪和尾巴，星星旋转 | 一段卡通打闹声，避免两段重叠 | 可用拟声词 |
| 嚼糖回血 | 打架结束 | 打完就当没发生 | 两只向两侧分开，嘴巴小幅开合、下巴交替抽动，呈现猫咪吧唧嘴；约 4.6s | 一次短嚼糖音，循环留安静间隙 | “嚼嚼嚼……” |

## 关键规则

1. **能反悔**：偏头和炸毛阶段随时拖走，立即解除应激。这是可以反复逗玩的核心。
2. **不能跳过叫板**：直接把一只猫拖到另一只上面，也先给约 650ms 的可见应激，再开打。
3. **边界不抖**：退出预警的距离略大于进入距离；阈值附近轻晃不会反复重播声音。
4. **不无限连战**：打完先分开，回血期间免战；再次开战需要完成恢复并有过足够距离的分离。狭小窗口无法分离时继续免战。
5. **多猫先配对**：优先配最近的两只，每只同一时刻最多参与一场，第三只不会被吸进已经开始的烟雾。
6. **声音有留白**：进入阶段时播一次，连续拖拽不重复开音轨；第一版默认静音，由用户打开。
7. **恢复能干预**：回血时能拖走、能点一下给短回应；吸附和烟雾短演出期间锁住这一对的普通拖动。

当前样机使用临时 SVG、源视频切分音效和本地音频导入；“猫爪伸出烟雾”、应激语音轮流接话留到正式美术阶段补齐。用户已纠正“嚼口香糖”指猫咪吧唧嘴，动作已改为嘴巴小幅开合与下巴交替抽动。

## DSH 接入事实与推荐路径

2026-11-17 阅读下列开源项目文档：

- [dsh-pet 源项目](https://github.com/PC2005-cloud/dsh-pet)：提供多实例、浏览器覆盖层、透明桌面窗和自定义 pet pack。
- [CONFIG.md](https://github.com/PC2005-cloud/dsh-pet/blob/main/CONFIG.md)：新增角色可以有独立动画池，同种类可有多只实例；内置宠物互撞默认是物理弹开。
- [API.md](https://github.com/PC2005-cloud/dsh-pet/blob/main/API.md)：桌面位置读取 `GET /pose?pet=`；演出占用锁、动画点播、位置控制、播放回执等。
- [CORDIS.md](https://github.com/PC2005-cloud/dsh-pet/blob/main/CORDIS.md)：浏览器页面内 `petApi7340.pose(petId)` 能读该页宠物的位置，不能当作桌面位置来源。

### 接入前必须实测的边界

- **拖拽撤锁**：上游文档写明用户拖拽会撤销演出锁，因此预警不能靠持续占用锁粗暴实现；先验证拖拽中点播能力。必要时在上游渲染器增加专用互动状态通道，等吸附开始才独占。
- **坐标单位**：浏览器位置是视口归一化坐标，桌面读取的坐标必须结合实际屏幕与缩放解释；多屏不能直接比较两个不相干的归一化数。
- **窗口呈现**：现有 API 文档没有证明第三方能同步隐藏两个窗口并创建一个跨窗口烟雾层。需要源码验证；可选由宿主补显隐接口与专用特效窗。
- **默认互撞**：内置的动量弹开可能抢在吸附前触发；正式实现要为哈吉咪配对演出暂停该对碰撞，结束后恢复。
- **取消与清理**：宠物关闭、删除、用户接管、插件卸载或锁丢失时，必须恢复另一只的可见状态、位置控制和正常动画。
- **原声与美术**：用户提供的图片目前作为造型参考；最终替换为固定锚点的透明动画。已从用户视频导出声段；不能把尚未试听确认的段落标注为特定拟声词或吧唧嘴。

## 验收

- 第一次玩，用户只需“再来一只”和拖拽就能完成整套循环。
- 不看文字，也能分辨独处、偏头、炸毛、烟雾和嚼糖五种状态。
- 距离还没贴上时，可以反复拉近拉远逗猫，不会被系统强行开战。
- 重叠后先有叫板再开打；打架画面只有一团共同烟雾。
- 打完是两只猫分开嚼糖，无死亡、胜负和强制照料。
- 关闭声音后全部互动仍然成立；同一阶段不因鼠标抖动重复播放。
- 两对猫同时接近不重复参战；回血阶段不会立即无限连战。
